# Шиномонтаж PRO — лендинг

Одностраничный сайт шиномонтажа в Симферополе (ул. Трансформаторная, 6).
Главная страница — один файл `index.html`: разметка, стили и скрипт, без сборки и библиотек. Открывается двойным щелчком в браузере. Рядом: `privacy.html`, `consent.html`, `api/lead.js`.

## Репозиторий
- Код в открытом репозитории https://github.com/aibakay/shinomontazh-pro (10.11.2026; приватный GitHub не дал создать из-за санкционных ограничений аккаунта). Репозиторий ОТКРЫТЫЙ: не класть туда пароли, токены, `.env*`, `.data/` (база, копии клиентов) — всё это в `.gitignore`.
- На ПК git и gh стоят (`C:\Program Files\Git\cmd`, `C:\Program Files\GitHub CLI`), gh вошёл как aibakay. После правок: коммит и `git push` в `main`.
- Репозиторий подключён к проекту Vercel (10.11.2026, `vercel git connect`, по согласию пользователя): каждый пуш в `main` сам выкладывает сайт и CRM в production (проверено, деплой shinomontazh-76ihegjzp). Правки можно делать с айфона через Claude Code на вебе. Пушить в `main` только проверенное; `.vercelignore` по-прежнему отсекает CLAUDE.md, `.claude`, `server.js`. Ручная выкладка `vercel.cmd deploy --prod --yes` тоже работает, но после неё обязательно запушить те же файлы, иначе следующий пуш откатит правку.

## Дизайн (редизайн 23.10.2026 по скиллу Taste Skill)
- Направление «Один мотив»: круг колеса повторяется на всех масштабах — огромное колесо на первом экране, красный круг с надписью по боковине в услугах, кнопки радиусов-кругов, диск в подборе цвета, буква «О» в подвале. Кнопки — полностью скруглённые, остальные углы прямые.
- Палитра: чёрное поле `--bg`, белые чернила, фирменный красный `--accent` (#d4202c) — только на действиях и на мотиве. Цвета полей (`--f-silver`, `--f-gold`, `--f-blue`) взяты из палитры порошковой покраски.
- Шрифты: Unbounded (заголовки) и Onest (текст) из Google Fonts — оба с кириллицей. Скилл предлагал League Spartan/Figtree, но в них нет кириллицы.
- Правила скилла: без подписей капсом над заголовками, без нумерации 01/02, без градиентов, теней в покое, тонких линий (кроме таблиц), эмодзи и карточек с иконками. Заголовки — не больше двух строк на любой ширине.
- Скиллы стоят в `.claude/skills/` (design-taste-frontend, frontend-design, high-end-visual-design, web-design-guidelines). Проверка: `node .claude/skills/design-taste-frontend/scripts/inspect.mjs index.html --out .taste-skill/after` и `lint.mjs index.html`. Node 24 установлен; если PATH не видит node, обновить его из системных переменных.
- Осознанно оставшиеся замечания инспектора: нет фото и видео (добавим позже), «чужие» шрифты (нужна кириллица), цена под нижней панелью на телефоне в какой-то момент прокрутки.

## Устройство
- Блоки по порядку: шапка (на телефоне — бургер), первый экран (карточка с протектором + колесо), услуги (`#services`, внутри пункт `#alignment`), цена по радиусу (`#calc`) и весь прайс с вкладками (`#price`), диски до/после — папки (`#discs`), цвет дисков (`#colors`), как проходит визит — гармошка (`#how`), вопросы (`#faq`), купон-запись + карта (`#contacts`), подвал со знаком PRO, нижняя панель на телефоне и плавающая кнопка на ПК.
- Колесо нарисовано один раз в скрытом SVG в начале `<body>` (`#rimBack`, `#caliper`, `#rimFront`) и подключается через `<use>`. В «Цвете дисков» колесо стоит по центру красного круга (`.c-wheel{inset:11%}`, 29.10.2026; пользователь просил не перерисовывать колесо, только сдвинуть). Цвет диска — CSS-переменная `--rim` (зарегистрирована через `@property`, поэтому плавно меняется).
- Появление: у контейнеров `.st` дети выезжают по очереди, `.rise` — плавное увеличение.
- Сцены прокрутки (добавлены 23.10.2026): GSAP 3.12.5 + ScrollTrigger (cdnjs) и плавная прокрутка Lenis 1.1.13 (unpkg, только на ПК с мышью). Заголовки `.h2` выезжают по словам, колесо на первом экране вкатывается и тормозит, круг в услугах раскручивается, плитки цен растут снизу, первая папка «до/после» темнеет под второй, колесо в «Цвете дисков» выкатывается на красный круг, буквы PRO в подвале поднимаются. Элементы с атрибутом `data-gs` анимирует GSAP — у них снимаются классы `.st`/`.rise`. Если библиотеки не загрузились или включено «уменьшить движение», остаются простые появления. При открытом меню или окне записи Lenis останавливается.
- Скрипт в конце файла: меню, вкладки прайса, ползунки до/после (`.ba`), работы по покраске (`WORKS`), цвета (`SW`), цена по радиусу (`MT` — шиномонтаж по типу авто и радиусу, `quote()`; 29.10.2026 по словам владельца балансировка входит в шиномонтаж — отдельно не прибавляется ни в калькуляторе, ни в «Переобувке под ключ» = только шиномонтаж (мойка — отдельная услуга, в пакет не входит); массив `BAL` и переключатель «Балансировка» убраны, балансировка отдельной услугой осталась в прайсе), гармошка, статус «открыто», купон, окно записи, анимация колеса.
- Незаполненные места выделены тегом `<em class="ph">`.
- Онлайн-запись: окно `#book` в 4 шага. Открывается любым элементом с `data-book` (значение — услуга заранее). Плитки цены открывают запись с подставленной машиной, радиусом и ценой. Купон в `#contacts` — короткая заявка (имя, телефон, услуга, когда удобно).
- Отправка заявки — функция `sendLead`. На хостинге заявка уходит на `/api/lead`. Если сайт открыт файлом с компьютера, заявка только пишется в консоль браузера.
- `api/lead.js` — серверная функция Vercel: проверяет заявку, ограничивает спам (5 заявок с адреса за 10 минут) и пересылает её в Telegram. Токен и чат — переменные окружения Vercel `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (заданы 23.10.2026, бот подключён и проверен). Токен бота в `index.html` класть нельзя. После смены переменных нужна повторная выкладка.
- Хостинг — Vercel, аккаунт «aibakay's projects», проект `shinomontazh-pro`, адрес https://shinomontazh-pro.vercel.app.
- Выкладка — через Vercel MCP `create_deployment`, target `production`: изменённые файлы передаются целиком, неизменённые — ссылкой `{file, sha, size}`. Выкладывать только `index.html`, `privacy.html`, `consent.html`, `api/lead.js` (не `.claude/`, не `.taste-skill/`, не CLAUDE.md). После выкладки сверять SHA1 живых файлов с локальными.
- Статус «Открыто / закрыто» считается по крымскому времени (UTC+3), часы — `OPEN`/`CLOSE` в скрипте.
- Цены взяты с прайса на двери; если прайс меняется, править таблицы в `#price`, массив `MT` и цены «от» в списке услуг и в `SERVICES`.

## CRM мастерской (`/crm/`, сделана 24.10.2026)
- Перенос Excel-таблицы «CRM Шиномонтаж PRO.xlsx» в веб: разделы Сегодня, Запись, Расписание (слоты по 30 минут, 08:00–22:30 — с 07.11.2026 по просьбе пользователя, выложено деплоем shinomontazh-bg0907lf8 вместе с удалением блока «Фото дисков», SHA1 /crm/ совпал; на сайте часы по-прежнему 08:00–20:00, пользователь просил менять только CRM), Работы, Клиенты, Хранение (бирка = номер записи, квитанция с наклейкой печатается из браузера), Отчёт (касса по дням, нал/карта/перевод, % мастеру, оплата хранения), Прайс.
- Интерфейс — `crm/index.html` (один файл, без библиотек). Сервер — `api/crm.js`, общий код — `api/_lib/` (`store.js` хранилище, `auth.js` вход, `schema.js` поля и подсчёт суммы, `seed.js` начальный прайс из Excel).
- Сумма работы считается на сервере как в Excel: «4 колеса» — цена за комплект, делится по колёсам; «1 колесо» и «услуга» — цена × количество; плюс скидка/доплата.
- Несколько услуг в одной работе (25.10.2026, только локально): в форме работы строки услуг и кнопка «+ Добавить услугу». Хранятся в поле `items` (`[{service, qty, price, unit}]`, до 20, проверка — `_item` в `schema.js`). Сервер сам ставит `service` = все услуги через запятую, `qty/price/unit` — по первой; сумма = сумма строк + скидка/доплата. Старые работы без `items` читаются как одна строка. Новая строка без услуги из прайса — «за услугу», 1 шт.
- Госномер — ключ клиента: заглавные, без пробелов, латинские двойники заменяются кириллицей. Новый госномер в записи, работе или хранении сам заводит клиента.
- Сотрудники и вход по коду (25.10.2026, только локально): экран входа — экранная цифровая клавиатура (0–9, ⌫, 4 точки, после 4-й цифры вход сам, ввод с клавиатуры тоже работает); ссылка «Войти по паролю» — для длинных паролей. Раздел «Сотрудники» (только владелец): «+ Создать сотрудника» — имя + код из 4 цифр, «Сменить код», удалить. Коллекция `staff` хранит только `pinHash` = HMAC от `CRM_SECRET` (при смене `CRM_SECRET` коды сотрудников перестанут подходить — задать заново). Код уникален и не может совпадать с паролем владельца/мастера. Сотрудник входит с правами мастера, в куке номер сотрудника; удалённый сотрудник сразу теряет доступ. В работе поле «Мастер» (`master`), по умолчанию — имя вошедшего сотрудника; в «Работах» колонка «Мастер». Локальный пароль владельца — в `.env.local` (вводится на клавиатуре).
- Б/у шины (25.10.2026, только локально): раздел «Б/у шины» — склад шин на продажу, коллекция `tires` (`received, size, radius, brand, season, price` — цена продажи за 1 шт, `qty` — принято, `sold` — продано, `note`; `radius` сервер берёт из размера «R16»). Фильтр по радиусу, итоги в штуках и по ценам продажи, «+ Приёмка», «Продать». Продажа — действие API `sell`: уменьшает остаток и создаёт работу `kind: 'sale'`, `tire: <id>` («Продажа б/у шин: …»). Продажи идут в кассу и отчёт, процент мастеру с них не считается (`toMaster()` в интерфейсе). Удаление такой работы возвращает шины на склад. Мастер/сотрудник может принимать и продавать, удалять — только владелец. Перенесено 18 позиций (72 шины) из Google-таблицы «Приемка б/у шин» (лист «Приемка», строка-пример Michelin не перенесена); цена есть только у Toyo 205/60 R16 (1000 ₽), остальным пользователь проставит. Копия базы до переноса — `.data/crm.backup-2026-10-25.json`.
- Правила кассы (25.10.2026, только локально): мастер/сотрудник записывает и правит работы только за сегодня (сервер отвечает `old-job`, форма прошлой работы у мастера только для чтения). У каждой работы сервер пишет `by`/`created` (кто записал), `editedBy`/`edited` (кто правил), `pct` — процент мастера на момент записи (смена процента в отчёте действует только на новые работы; у работ без `pct` берётся текущий), `booking` — запись, из которой создана работа (запись сама становится «Приехал»). Сумма работы не может быть меньше нуля. В продаже б/у шин название и количество не меняются (только цена, оплата и прочее); у шин мастер не меняет «Принято»/«Продано» у принятых позиций. Хранение: поля `paidOn` (дата оплаты, по умолчанию сегодня; у старых — дата приёма) и `payBy` (Нал/Карта/Перевод); оплата хранения входит в кассу дня и в нал/карту/перевод. Отчёт: колонка «Из них хранение», «Мастерам» по проценту каждой работы, таблица «Зарплата по мастерам» (по полю «Мастер», без продаж шин). Кука сотрудника содержит метку его кода (`v`): смена кода сразу выкидывает его из CRM.
